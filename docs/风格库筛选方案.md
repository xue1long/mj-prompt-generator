# 风格库筛选方案（A 档 / B 档 / C 档）

> **状态**：**A 档与 B 档已实施**（2026-11-05）｜ C 档不做
> **依据**：上游规则见 [`Midlibrary筛选规则分析.md`](Midlibrary筛选规则分析.md)；数据事实为本项目实测（见第二节）。
> **决策来源**：本轮 grilling 六问 —— 结构分两个 tab（Q1-b）、A 档两个 tab 各一条筛选条（Q2-a）、术语按语义命名（Q3）、hash 为筛选唯一状态源（Q4-a）、A 档只上一套计数口径（Q5-b）、B 档数据源改为等新站点采集完成后从站点抓（Q6 修订）。
> **落地记录**：见文末第十节（含三处实现期修正与一处 B 档偏差）。

---

## 一、目标与非目标

**目标**：把 Midlibrary 的筛选规则里*能搬的部分*搬到本项目的风格库上，让 8,960 条风格条目从「一页页翻」变成「按条件收窄」。先落**不依赖分面数据的 A 档**，把界面、状态、计数口径这些地基打好；分面（term / colour）留到 B 档。

**非目标**：

- 不做 Midlibrary 全站式的导航结构（16 类共处一个面板）——本项目没有那个形态，见第二节结论 3。
- **不给 156 条手写摄影词库加筛选面板**。156 条用 5 个 tab + 22 个二级分类 + 全局搜索已经够；加 5 维面板是负资产（奥卡姆）。
- 不引入 `kind` 这类死参数、不做 `q→best` / `like→similar` 的隐式排序改写（本地单人工具，URL 语义含糊没有收益）。

---

## 二、数据事实（先量再设计）

我们的风格库快照 `config/styles.yaml` 共 **8,960 条**，分 **12 个类目**（11 个画家类目 + `sref-styles`，互斥划分，之和 = 8,960）。

| 维度 | 数据来源 | 规模 | 判断 |
|---|---|---:|---|
| `category` | manifest | 12 类 / 8,960 | ✅ 全量、互斥 |
| `tested` | manifest `testedMark` | 4,407 | ⚠️ 退化：画家 **458 / 4,322 = 10.6%**，风格码 **3,949 / 4,638 = 85.1%** |
| `pick` | manifest `isPick` | 554 | ⚠️ 退化：**艺术家 0 条**，等于「只要码」 |
| `publicDomain` | manifest `isPublicDomain` | 733 | ⚠️ 退化：只有画家有，等于「只要部分画家」 |
| `term`（68 词 / 10 组） | `sites/midlibrary/data/details.json` 的 `t` | **2,286 / 8,960 = 25.5%** | ❌ A 档不能用 |
| `colour`（91 色） | 同上 `c` | 同 term | ❌ 同上，风格码只有 **6.2%** |
| 搜索 `q` | 现有 Ctrl+K | 全量 | ✅ |

分面覆盖按类目（实测）：

| 类目 | 有分面 | 覆盖率 |
|---|---:|---:|
| `illustrators` | 681 / 919 | 74.1% |
| `filmmakers` | 67 / 118 | 56.8% |
| `printmakers` | 22 / 43 | 51.2% |
| `photographers` | 347 / 684 | 50.7% |
| `painters` | 597 / 1,546 | 38.6% |
| `architects` | 41 / 107 | 38.3% |
| `designers` | 61 / 165 | 37.0% |
| `fashion-designers` | 44 / 135 | 32.6% |
| `various-artists` | 94 / 309 | 30.4% |
| `street-artists` | 12 / 60 | 20.0% |
| `sculpture-installation` | 32 / 236 | 13.6% |
| `sref-styles` | 288 / 4,638 | **6.2%** |

**三条结论**：

1. **`tested` / `pick` / `publicDomain` 在我们这批数据上不是「质量维度」，而是「条目类型」的代理**——因为它们的分布几乎只落在码或只落在画家上。照抄这三个开关，用户点下去得到的是「换了类目」。
2. **term / colour 覆盖 25.5% 且极不均匀**。现在上分面筛选不是「筛空」，而是**假阴性**：约 75% 的条目永远不可能被任何 term 命中。用户会以为库里没有，而不是以为数据缺失。**这是 B 档不能先上的唯一理由。**
3. **`category` 在两个 tab 里都退化**：艺术家的 12 类里 11 类已经是现有二级分类；码 tab 里全是 `sref-styles`（常量）。所以本项目没有 Midlibrary「16 类共处一个面板」的形态——这正是本方案与上游形态分道的地方。

## 三、规则判决：搬什么、改什么、不搬什么

| 上游规则 | 判决 | 本项目的处理 |
|---|---|---|
| URL 即状态（面板不持状态） | ✅ **搬** | hash 是筛选的唯一状态源，见 4.3 |
| 划分型维度 OR、标签型维度 AND | ✅ **搬** | A 档用不到 OR（无多值划分维度），B 档按此实现 |
| 计数按维度分口径 | ✅ **搬，但 A 档只用一套** | A 档统一「结果集内」；B 档恢复两套口径（见 5.2） |
| 已选条件条 + Reset 回显 | ✅ **搬** | 「已选条件条」，见 4.1 |
| 12 个面板分组压平成同一个 AND 标签集 | ❌ **不抄** | 文档自己实测：`abstract ∧ characters` 只剩 3 条。B 档必须**组内任一、组间全部** |
| `kind` 死参数 / `q→best` / `like→similar` | ❌ **不抄** | 本地单人工具，语义含糊不如直说 |
| 未知参数静默忽略、返回 0 条空列表 | ❌ **不抄** | 丢弃该参数并修正 URL，UI 提示「已忽略不支持的筛选：<参数名>」 |
| 零计数选项：有的照显、有 0 条不渲染 | ⚠️ **取一种** | 显示但置灰，并标出计数 0；不要两种行为混用 |

## 四、A 档：本方案要做的

### 4.1 范围与维度

两个 tab 各一条筛选条，**共享同一个组件与同一套口径**，筛选状态**各自独立**（互不干扰）。

| tab | 条目 | 可用维度 |
|---|---:|---|
| 👤艺术家/摄影师 | 4,323 | 搜索 `q` + **只看实测**（450 条）+ 现有二级分类（手写 6 个 + 风格库 11 个，不改） |
| 🎨风格参考码 | 4,638 | 搜索 `q` + **编辑精选**（554 条）+ 只看实测（3,949 条，弱但保留，**标出计数**） |

> 「只看实测」在艺术家侧是 10.4% 的真筛选，在码侧是 85% 的弱筛选。两处都保留同一个开关，但**计数必须写在选项上**，让用户自己判断值不值得点。
>
> 注意 **450** 不是上游的 458：并入词库时 22 位与手写条目重名的画家被跳过，其中 8 位是实测过的，所以合并后的艺术家 tab 里实测条目是 450 条。

### 4.2 语义

- 同一维度多值：**任一**（OR）。A 档只有布尔维度，暂不涉及。
- 不同维度之间：**全部**（AND）。
- **A 档只上一套计数口径：结果集内计数。** 即选项上显示的数字 = 当前已选条件下、再选该项会得到的条数。理由：A 档没有多值划分维度，上游那套「划分型反作用域」无处可用，硬套只会增加解释成本。两套口径留给 B 档。

### 4.3 URL 契约（hash 是筛选的唯一状态源）

```
#/artists?tested=1&q=puu
#/style-codes?pick=1&q=ghibli
```

- **参数白名单**：`q`、`tested`、`pick`。其余一律**丢弃并修正 URL**，UI 顶部提示一次。
- 布尔参数：出现即 `1`，不写 `=0`（`?tested=0` 视为未生效并丢弃）。
- 刷新、后退、分享同一 hash 都能复现同一筛选结果。
- localStorage 只保留现有会话（已选提示词、主体环境、参数值），**不存筛选状态**。
- 组装行为不受筛选影响：筛选只改变「显示哪些卡片」，不改变「已选提示词」。

### 4.4 代码落点

| 文件 | 改动 |
|---|---|
| `src/utils/facetFilter.ts` | **新增**。纯函数：`applyFilters(entries, state)`、`countOf(entries, state, dim)`。无 Vue 依赖，便于单测 |
| `src/utils/filterHash.ts` | **新增**。纯函数：`parseFilterHash(hash, whitelist)` / `buildFilterHash(path, state)`，负责丢弃未知参数 |
| `src/stores/styleStore.ts` | 加 `filterState`（码侧）与 `filteredCodes`、`testedCount`、`pickCount` |
| `src/stores/promptStore.ts` | 艺术家侧：在合并后的分类上做筛选，暴露 `filteredSubCategories` |
| `src/components/PromptBuilder/FilterBar.vue` | **新增**。共享组件：搜索框 + 开关 + 已选条件条 + Reset + 「N 条」 |
| `src/components/PromptBuilder/StyleLibrary.vue` | 接入 `FilterBar`，换成 `filteredCodes` 渲染 |
| `src/components/PromptBuilder/PromptSubCategoryList.vue` | 接入 `FilterBar`（艺术家侧），与现有「显示更多」共存 |
| `tests/facetFilter.test.ts` | **新增**。守：布尔维度 AND、计数表、空参数 |
| `tests/filterHash.test.ts` | **新增**。守：白名单、未知参数丢弃、往返幂等 |

### 4.5 验收标准（可执行）

1. `#/style-codes?pick=1` → **554 条**；再叠 `&q=ghibli` → 交集，且条数 = 手动算出的交集数。
2. `#/artists?tested=1` → **450 条**（手写词库的 23 条没有实测标记，不计入；22 位重名画家被跳过，其中 8 位实测过）。
3. 刷新后筛选不变；浏览器后退一步，回到上一组筛选。
4. `#/style-codes?category=painters`（该 tab 下 `category` 是常量）→ 参数被丢弃，URL 被修正，UI 提示「已忽略不支持的筛选：category」。
5. 已选条件条只显示生效条件；Reset 清空后 URL 回到 `#/style-codes`。
6. 「N 条」数字与网格实际渲染的条目数一致（分批显示时以总数为准）。
7. `npm test` 全绿（新增两个用例文件）；`npm run verify` 覆盖「筛选 → 计数 → 填 --sref」链路。

## 五、B 档：分面筛选（已实施）

### 5.1 数据源：站点导出的 `details.json`

采集已完成：`sites/midlibrary/data/details.json` 覆盖 **10,140 / 10,140** 条，我们子集 **8,960 / 8,960 = 100%**（每条 3–10 个分面词、1–9 个主色）。本项目从这份站点导出物读，不自己抓上游。

实际拿到的契约（`tools/build-styles.ts` 的 `MidlibraryDetail`）：

| 字段 | 内容 | 用途 |
|---|---|---|
| 键 | 条目 id（与 `manifest.json` 的 id 对齐） | 分面挂到条目上 |
| `t` | `[[组名, [[显示名, 全站计数, slug], …]], …]`（10 组 / 68 词） | 分面词维度 |
| `c` | `[[hex, 色名, 占比, slug], …]`（96 色，按占比降序） | 主色维度（占比顺序即条目里的顺序） |

覆盖度写进 `source.facetCoverage`；不足 100% 时筛选条上会显示一行提示。

### 5.2 语义

- term / colour：**组内任一（OR）、组间全部（AND）**。这是与上游最关键的一处分歧，理由见 `Midlibrary筛选规则分析.md` 第十二节。
- 主色：同维度多值，取并集。
- 零计数选项显示但置灰（不隐藏）。
- **偏差：两套计数口径没有恢复。** 方案原本打算在 B 档恢复「划分型维度反作用域 + 标签型结果集内」两套口径。实现时发现本项目**没有可筛的划分型维度**——类目已经是 tab 与二级分类，码 tab 里类目是常量。硬造一个类目筛选器只会多一层冗余，所以统一用一套口径：**选项上的数字 = 在当前条件基础上再打开该项会得到的条数**（与 A 档同源）。

### 5.3 覆盖度

- 覆盖率写进 `source.facetCoverage`，界面在 < 100% 时显示「分面数据覆盖 N% 的条目」。
- 当前是 100%，所以这行不出现；字段留着，采集退化时立刻能看到。

### 5.4 验收标准（实测值）

1. 组内任一：`term=characters&term=landscapes` → **4,261 条**（两词各 2,398 / 4,026 的并集，不是交集）。
2. 组间全部：`term=detailed&term=characters` → **2,673 条**（交集）。
3. 跨维度与：`term=detailed&colour=blue` → **602 条**。
4. 单维度：`term=detailed` → 3,629 条；`colour=blue` → 824 条。
5. 面板渲染 68 个分面词 + 96 个色块。
6. 任何 term 组合下结果集为空时，UI 提示「该条件下没有匹配的条目」而不是空白。

## 六、C 档：明确不做

| 不做 | 理由 |
|---|---|
| `kind` 参数 | 上游是死参数（无 UI 生成、任意取值 0 条），抄它等于抄一个 bug |
| `q` 自动切 `best` 排序、`like` 自动切 `similar` | 隐式改写让 URL 语义含糊；本项目排序与筛选分开表达 |
| 未知参数静默忽略 | 单人工具，静默失败比报错更贵 |
| 把 term 压平成一个 AND 集 | 实测 `abstract ∧ characters` 只剩 3 条，等于把库筛空 |

## 七、术语（同步写入 `CONTEXT.md`）

| 术语 | 定义 | 避免叫 |
|---|---|---|
| **筛选条件** | 一个已生效的收窄条件（搜索词、只看实测、编辑精选） | 过滤器、参数 |
| **已选条件条** | 把当前生效的筛选条件逐条列出、可单条移除的横条 | 芯片条、chip |
| **筛选结果** | 满足全部筛选条件的条目集合 | 命中集、结果集 |
| **筛选维度** | 一组可筛的取值（A 档：实测、精选；B 档：类目、分面词、主色） | 分面、标签组 |
| **分面词**（B 档） | 风格条目上的描述性标签，按组归类（风格质量 / 主题 / 技法…） | 标签、term |
| **组内任一、组间全部** | 同组多个取值取并集，不同组之间取交集 | 组内或、跨维与 |

## 八、成本、风险与回退

**A 档**：新增 2 个纯函数模块、1 个组件、2 个测试文件，改 3 个既有文件。无数据依赖，可独立验收。

**B 档**：数据已齐（100% 覆盖），无外部依赖。风险两条——

1. **覆盖度回退导致假阴性**（对策：`source.facetCoverage` 写进快照，界面在 < 100% 时提示）；
2. **字段契约漂移**（对策：适配逻辑集中在 `tools/build-styles.ts`，站点改字段只改这一处）。

**体积代价**：分面词与主色让 `config/styles.yaml` 从 2.50 MB 涨到 5.14 MB，产物体积随之增加；换来的是一条条目可以被 68 个词与 96 个色筛。

**回退**：A 档的筛选状态与 UI 是纯叠加层，整体去掉不影响组装与参数；B 档的分面是再叠加一层，去掉后退回 A 档。

### 三处实现期修正（方案里没写到、写代码时才暴露）

1. **「只看实测」的条数是 450，不是 458。** 458 是上游 4,322 位画家里的实测数；并入词库时 22 位重名画家被跳过，其中 8 位实测过。
2. **「已忽略的筛选参数」提示不能挂在 tab 切换上清除。** 从 hash 恢复时切 tab 也走同一条路径，清了就等于刚提示完就自己抹掉（见 ADR-0010）。
3. **冒烟验证的刷新不能用 `networkidle2` 等。** 风格库几百张懒加载图会让它长时间不空闲，改用 `domcontentloaded`；另外刷新后 hash 可能把标签页带到风格库，读主体输入框前要先切回「主体与环境」。
