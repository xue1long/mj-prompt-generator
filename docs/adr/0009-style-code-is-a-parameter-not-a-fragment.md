# 风格参考码是参数不是片段：只进参数区，技能包不含风格库

Midlibrary 的两类数据性质不同。风格名（`by Puuung`）是提示词片段，能进词库参与组装；风格参考码（`--sref 3383230063`）是**参数**。本项目的参数区本来就有 `--sref`（`styleRef`），但它的 placeholder 写的是「输入图片URL」——用户既不知道该填码，也无处可查。

决定：风格参考码**不进词库**，单独做一个「风格参考码」页签：搜风格名或码 → 看样例图 → 一键填进 `--sref` 参数框。技能包**不含**风格库。

## 考虑过的选项

- 把码也做成词库条目：码会落进「其他」片段区，最终提示词变成 `…, --sref 3383230063 --ar 16:9`；参数区再出一个 `--sref` 就重复了。更糟的是「片段」这个概念开始装参数，组装模型被污染。
- 给码加一个位置标签：位置标签只有四个（artist / camera / lighting / other），它们决定的是**片段在正文里的位置**；参数在正文之后另有一段，位置标签表达不了这件事。
- 技能包也带上风格库：`vocab-photography.md` 会涨到几百 KB，agent 读不动；风格码是「查得到就行」的数据，不是写作方法论需要的词表。
- 技能包单独出一份 `vocab-styles.md`：agent 真正需要的是「怎么写提示词」，八千个风格名对写作是噪音。

## 后果

- 「风格参考」参数的 placeholder 与说明改成「输入风格码或图片URL」，并指向风格参考码页签。
- 风格参考码的界面出口只有一个：填进参数框。「复制」按钮给的是完整一行 `--sref <码>`，供手抄到别的工具。
- 技能包边界与 ADR-0006 同形：**引用不复制**。技能包里不出现风格码与风格名，`npm run export:vocab` 的产物保持只含摄影术语。
- 风格参考码不进词库这条不变量由 `tests/styleMerge.test.ts` 守住。
- 词库里的「风格条目」与「风格参考码」是两回事：前者是提示词片段，后者是参数取值。术语上不混（见 `CONTEXT.md`）。
