# ADR-0025：拆解的三层可信度、时间的两个口径、参数维度不可研究

- **状态**：已采纳（2026-11-11）
- **相关**：ADR-0015（探索榜灯箱展示拆解）、ADR-0010（筛选状态写在 URL）、ADR-0022（导出与数据层裁决）、ADR-0024（候选词条视图）
- **来源**：`docs/第一性原理校验报告.md` 2.5 / 2.7 / 2.8

---

## 背景

报告 2.5 / 2.7 / 2.8 是三条独立的「需完善」，但实测后发现它们指向同一件事：**研究样本库里的字段，可信度与口径没有在界面上被分清**。

| 报告 | 原文判断 | 实测复核 |
|---|---|---|
| 2.5 | 942 条拆解里 889 条规则解析与 53 条精拆混在一起，界面只靠角标文字区分 | 成立。且 `tools/rule-decompose.mjs` 的保留判据只保护「手工精拆」，全量跑一次会把 50 条 LLM 精拆**静默降级**成规则解析 |
| 2.7 | 954/957 条批次键 ≠ 实际入队日期 | 成立且更严重：**968/971** 条不同；批次 `2026-11-05` 下的真实生成日横跨 **28 天**（最早 2026-10-06） |
| 2.8 | `version` 957/957 全是 `8.2`，参数段只有 8 条误命中 | 成立：971/971 全是 `8.2`；正文含 `--` 的 9 条**全部**是 `--massive` / `--perfect` 这类正文破折号；`paramTail` 全空 |

### 2.5 的实测分层

| 来源 | 条数 | 含义 |
|---|---|---|
| 手工精拆 | 3 | WorkBuddy 手工分解，已验收基准 |
| 逐条精拆 | 50 | LLM 语义判断，逐条给出 |
| 规则解析 | 889 → **918** | 确定性关键词匹配，启发式推断 |
| 无拆解 | 29 → **0** | 11-08 有 15 条、11-10 有 14 条 |

数据层已有 `decomposition.source` 字段（由 YAML 的 `model` 经 `modelSource()` 映射），灯箱也已显示来源徽章。**缺的只是「按可信度筛选」的入口。**

### 2.8 的实测证据

| 项 | 实测 |
|---|---|
| `version` 分布 | `8.2` × **971**（零区分度） |
| prompt 含 `--` 的条数 | **9 / 971**，且 6 条样例全是误命中：`--massive` / `--perfect` / `--a` / `--shifting` / `--An` / `--which` |
| `paramTail.text` | 971/971 全为空 |
| 结构化参数字段 | 只有 `aspect`（36 种）与 `version`，**无** `--ar` / `--sref` / `--v` |

结论：这批数据**无法支撑任何参数维度的研究**。`aspect` / `version` 是上游字段，不是作者写进 prompt 的。

## 决定

### 2.5 —— 分层可用，而不是把数据擦干净

1. **加「拆解来源」筛选维度**（`multi`：手工精拆 / 逐条精拆 / 规则解析 / 无拆解），进 URL。
2. **加「只看可信拆解」快捷开关** = 手工 + 逐条。它是**多选的一种写法**，不是独立状态位 —— 否则会出现「开关开着、多选里又勾了规则解析」这种自相矛盾的状态。URL 里体现的就是 `decomp` 多选本身，刷新与分享都自然复现。
3. **修 `rule-decompose.mjs` 的保留判据**：从 `/手工/` 扩到 `/手工|精拆/`。规则解析器只能覆盖规则解析层与缺失项，**不得覆盖比它更可信的层**。
4. **缺口用规则解析补齐到 0**，如实落在最低可信层。补齐是为了让「971/971 都有拆解」成为可断言的不变量，不是为了让数据看起来完整。
5. **不在这一轮做 LLM 精拆升级** —— 环境里没有 `MJ_DECOMPOSE_API_KEY`（无 `.env`），29 条手工精拆的工作量与收益不匹配。等采集侧能跑 LLM 时整批升级更合理。

### 2.7 —— 两个口径都留着，但必须分得清

6. **加「生成日期」筛选维度**（`multi`，`YYYY-MM-DD`，**新 → 旧**排列，共 34 天）。这是报告说的「真实查询能力是现成的，只是口径没对齐」。
7. **保留「采集批次」**（它有自己的用途：判断数据新鲜度、追踪滚动窗口）。只把它在下拉与 `aria-label` 里写成「采集批次」，加 `title` 说明它是什么。
8. **抽 `webui/js/gen-date.js`**，让界面筛选与样本导出共用一份日期换算。
9. **口径定为本地时间**：UTC 与本地（UTC+8）在实测数据上有 **287 条**落在不同日期。取本地时间的理由是「使用者看的是自己日历上的哪天」，且第 10 步的导出已经这么做了 —— 换口径会让旧导出与界面自相矛盾。

### 2.8 —— 承认不可研究，而不是用推断值冒充

10. **灯箱参数尾区加两条注记**（虚线边框，视觉上是注记不是数据）：
    - `param-absent`：这条正文没写参数，参数尾是按正文里的 `--` 实打实切出来的，没有就显示没有；
    - `param-caveat`：整批数据的参数维度**不可研究**，附上实测依据（`version` 全 `8.2`、9 条误命中）。
11. **不进采集侧补参数**。报告给了这个选项，但它要求改采集链 + 重新采集 971 条，且依赖上游 `prompt` 对象里真有结构化参数 —— 未验证。本轮不做，登记为待验证。

## 考虑过的选项

| 选项 | 为什么没选 |
|---|---|
| **A. 只把规则解析重跑一遍，让数据「干净」** | 会丢掉 50 条 LLM 精拆与 3 条手工精拆 —— 用低可信数据替换高可信数据，是负向改动 |
| **B. 「只看可信拆解」做成独立状态位** | 与 `decomp` 多选双写，必然出现互相矛盾的状态。做成多选的快捷写法后只有一处真相 |
| **C. 用生成日期替换采集批次** | 批次不是错的数据，是另一种口径（判断新鲜度、追踪窗口）。替换会丢信息 |
| **D. 日期用 UTC** | 与第 10 步的导出口径冲突；且对使用者来说「我今天看到的榜单」是按本地日历理解的 |
| **E. 把 `paramTail` 从界面删掉** | 删掉之后「为什么没有参数」这个问题更没人能回答。留着并说清，比藏起来好 |
| **F. 缺的 29 条由 LLM 逐条精拆** | 质量更高，但需要 API key（环境里没有）或手工产出 29 × 七段；本轮先用规则补齐把缺口归零，升级留到能跑 LLM 时整批做 |

## 后果

- **正面**：研究样本库现在能按「可信度」与「真实时间」筛 —— 这两件事是研究结论可信的前提，此前都只能靠人记住。
- **正面**：**缺口归零**（971/971），并有断言钉住（`拆解缺口归零（第 13 步）`），采集到新作业后悄悄退回会被抓到。
- **正面**：修掉一个隐患 —— `rule-decompose.mjs` 只保护手工精拆，全量跑会静默降级 50 条。修完之后这条路径安全了。
- **正面**：日期换算从「两处各写一份」收敛到一处，且有测试直接断言「界面与导出对同一条作业给出同一个日期」。
- **代价**：工具栏多了 2 个下拉 + 1 个开关（共 7 个筛选控件），窄屏下更挤。窄屏页签遮挡是既有缺陷，本步未处理。
- **代价**：`data-explore.js` 从 3.16 MB 增至约 3.7 MB（29 条拆解 × 七段）。
- **约束**：`decomp` 的取值域必须与 `build-webui-data.mjs` 的 `modelSource()` 同域，否则筛选选项与数据对不上。两处都写死在同一组字符串上，改一处要改另一处。

## 验证记录

| 项 | 结果 |
|---|---|
| 数据补齐 | 942 → **971**；规则解析 889 → 918；**53 条可信层内容逐字未变** |
| 结构合规 | 971/971 都有 7 段 + ≥10 项 health + paramTail |
| `npm run verify`（源码 / `--dist`） | **120/120**（新增 7 条断言） |
| `npm test` | **18 文件 / 333 用例**（基线 17/324 + 新增 `genDate.test.ts` 9 例） |
| `npx tsc --noEmit` | 6 个错误（与第 12 步基线一致，零新增） |
| `npm run build` | 30 文件 / 7.13 MB / 22 个 JS / 4 个 HTML |
| 分面计数自洽 | 拆解 3 + 50 + 918 = 971；生成日期 34 天合计 971 |
| 组合语义 | 手工 + 规则 = 921（`multi` = 组内任一） |
| 运行时报错 | 零 |

新增的 7 条 verify 断言：拆解缺口归零 / 拆解来源分层不重不漏 / 只看可信拆解 = 手工+逐条且进 URL / 列表同步收窄 / 刷新复现 / 生成日期下拉计数与真实命中一致 / 灯箱把「参数维度不可研究」说清楚（含「渲染层不得漏出 markdown 星号」）。
