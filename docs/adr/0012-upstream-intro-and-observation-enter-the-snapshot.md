# 上游的简介与风格描述收进风格库快照

风格条目只有原文名，上游不给中文名——所以在卡片上认人只能靠名字，而光有名字认不出人（"Alan Fearnley" 是谁？画什么的？）。隔壁仓 `ai-video-imge-prompts` 抓下来的 `sites/midlibrary/data/details.json` 里其实有每一条的作者介绍（`a`）与风格描述（`o`），以前生成脚本只从中取分面词与主色，把这两段文字丢掉了。

决定：**生成脚本把 `a` 与 `o` 一并收进 `config/styles.yaml`**，界面用简介的第一句做卡片副标题，全文与风格描述放进详情弹窗。

## 考虑过的选项

- 运行时去抓上游详情：应用是"双击即用"的离线产物（ADR-0003），运行时不能依赖网络，也不能依赖隔壁仓的目录结构。
- 只留简介的第一句（0.54 MB）省体积：详情弹窗里就只能看到半句话，读者要判断"是不是我想找的风格"时没有依据。
- 把文本放进手写词库 `config/prompts.yaml`：手写源会被生成物淹没，diff 与评审都失去意义（ADR-0008 的同一条纪律）。
- 用机器翻译把 4300 个名字译成中文：没有数据源，译名无人校对也无人维护；而上游的简介本身就带国籍与流派（"South Korean illustrator known for…"），识别力足够。

## 后果

- 快照从 5.4 MB 涨到 8.6 MB（简介 1.45 MB + 风格描述 1.37 MB），构建期内联进产物后 JS 包约 7.5 MB。解析发生在构建期，运行时只是 JSON.parse。
- 许可面扩大了一点：文字与图片来自同一站、同一份许可（个人学习用途，署名 + 回链），展示方式不变（逐条回链 + 页脚署名）。
- 上游只给原文名的风格参考码不收简介——码是参数，没有"是谁"的问题（ADR-0009）。
- 11 条艺术家条目上游没有简介（占 0.3%），卡片上退回显示英文写法，不留空白。
