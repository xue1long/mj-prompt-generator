# ADR-0028：研究样本的两轴分类（表现媒介 × 画面主体）

- **状态**：已采纳（2026-11-11）
- **相关**：ADR-0010（筛选状态写在 URL）、ADR-0017（选项只列本地真实覆盖）、ADR-0025（拆解的三层可信度与两个时间口径）、ADR-0022（导出与数据层）
- **来源**：用户要求「用二层分类，大分类里有写实、二次元，二层里面都有人像」；上一轮报告 2.x 的「图片类型」筛选项缺失

---

## 背景

用户的原话是「二层分类」：一层大分类（写实、二次元…），二层细分（人像、动物、风景…），并举例「写实下面有人像，二次元下面也有人像」。

这句话看起来像一棵树，实际上是**一个矩阵**：人像并不「属于」写实，它是写实风格与二次元风格下都可能出现的主体。先把这一点在数据上验证清楚，再决定形态。

### 数据里没有内容标签

研究样本库的 971 条作业**没有任何内容标签字段**。可用的只有文本：

| 字段 | 覆盖 | 是不是图片类型 |
|---|---|---|
| `aspect` | 971/971（36 种） | 版式，不是内容 |
| `tags`（style / lighting / angle / emotion） | 971/971，但 `style` 只有 413 条非空、187 种长尾词 | 风格，不是主体 |
| `summary` | 971/971，一句话中文描述 | **最有用的语义线索，但是自由文本** |
| `segments`（七段） | 971/971 | 拆解结果，第 1 段是主体 |
| `framework` | 人物画像 430 / 物体描述 93 / **空 448** | 拆解**模板名**，只覆盖一半 |
| `sref` | 82/971 | 风格参考码 |

结论：想加内容维度的筛选，只能自己推。

### 实测：两个轴确实正交，但都不完整

按规则推算（词表 v1，判定顺序见下），971 条的分布：

| 表现媒介（怎么画） | 条数 | | 画面主体（画什么） | 条数 |
|---|---|---|---|---|
| 写实 / 摄影 `realistic` | 304 | | 人像 / 人物 `person` | 407 |
| **未声明媒介** `undeclared` | **298** | | 自然 / 风景 `nature` | 167 |
| 插画 / 绘画 `illustration` | 254 | | **未判定主体** `unknown` | **170** |
| 抽象 / 实验 `abstract` | 31 | | 动物 `animal` | 90 |
| 平面 / 设计 `graphic` | 30 | | 建筑 / 室内 `architecture` | 87 |
| 二次元 / 动漫 `anime` | 30 | | 静物 / 食物 `still` | 33 |
| 3D / CG `cg3d` | 24 | | 科幻 / 奇幻 `scifi` | 17 |

- 两轴各自求和都是 **971**（单值互斥，可加总）。
- 两层都能判定的样本 **591 条（60.9%）**。
- 7 × 7 = 49 个格子里 **42 个非空**。
- 用户举的例子真实存在但规模很小：**二次元 × 人像 = 15 条**。二次元总共只有 30 条 —— 这批数据是 Midjourney 社区作品，绝大多数是写实。

### 比例不稳定，这是必须写进界面的事实

同一批数据换一版词表，「未声明媒介」在 **28%–34%** 之间浮动（实测 290 ↔ 334）。所以界面上的数字只能当**同一次口径下的相对量**看，不能跨版本引用，更不能当结论。

## 决定

### 1. 两条正交的轴，不做树

一层叫**表现媒介（medium）**，二层叫**画面主体（subject）**，两者独立筛选。

做成树的代价是具体的：想看「所有人像（不分媒介）」时，得把每个媒介下的人像各勾一次。而「人像 407 条」正是筛选要回答的问题。矩阵形态（行媒介 × 列主体）表达不了「整列」，且 7 × 7 在 404px 侧栏里放不下，故不做矩阵面板。

### 2. 每层单值互斥

一条作业在一层只归一个媒介、在二层只归一个主体 ⇒ 各档计数之和恒等于 971，可以写成断言。代价是「水彩风动漫人像」只能记一个（按词表与来源层顺序取先命中的）。多标签的如实性留给灯箱，不进筛选。

### 3. 「未声明」「未判定」单列一档，且可勾选

不默认归入写实 —— 默认归并会把推断写成事实，一旦「写实 65%」进了研究结论就再也纠不回来；不设这一档则会让「写实」永远少 298 条，而用户不知道它们去哪了。**「没有结论」与「有结论但不确定」必须分开显示**，与拆解来源分三档是同一条原则。

### 4. 判定：强度优先于来源层

三层文本依次是 `tags.style` → `summary` → `全部段落 + prompt`（主体轴的第一层是**第 1 段主体段**）。层次内按档位表顺序取第一个命中。

但**强弱信号先于来源层**：先跨三层找强信号，整条作业没有强信号时才用弱信号。

这条是实测踩出来的。有一条样本的 `tags.style` 是 `["collage","cinematic"]`，而 prompt 明写 `Full body cinematic photograph` —— 若两者平权，档位顺序会把它判成「抽象」。所以：

| 强度 | 例子 | 规则 |
|---|---|---|
| 强 | `photograph` / `watercolor` / `anime` / `3d` / `logo` | 本身即媒介名词，单独出现就能定 |
| 弱 | `collage` / `surreal` / `poster` / `排版` | 可只是风格修饰，只在没有强信号时才用 |

同样的坑在主体轴上是 `space`：摄影语境里 `negative space`（留白）高频出现，若不限定短语，人像与静物会被大批判成科幻。故只认 `outer space` / `deep space` / `space station`。

**不映射的词**：`cinematic`。它可以是实拍也可以是动画，只知道「电影感」不足以定媒介。

### 5. 不复用风格榜的「题材（kind）」

风格榜已有 `portrait` / `landscape` / `still_life` / `hot_cup_of_coffee` / `tree` / `house` / `animal` / `street_scene` 八类，写进 `CONTEXT.md` 的「题材」词条。

不复用的理由：那八类是**给 8 张示例图配的固定文件名标签**，细到 `hot_cup_of_coffee`，且没有「科幻 / 奇幻」与「图形」。样本库有 17 条科幻、30 条平面设计，硬套会全掉进「未判定」。两套词表服务两种语料，合并只会让一方失真。

### 6. 分类是规则推算，不是人工标注 —— 界面与导出都必须写明

- 标签常驻后缀：`表现媒介 · 规则推算`、`画面主体 · 规则推算`，`title` 里说明「非人工标注，比例随词表浮动，不可直接当结论引用」。
- 灯箱里两轴徽章后跟一句「规则推算 · 非人工标注」。
- 导出：JSON 每条带 `表现媒介` / `画面主体`（稳定 slug）+ `分类来源: "rule"`；Markdown 概览表加两列（中文名），并附一条免责说明。
- 为什么不用 tooltip 承载这条信息：截图带不走 tooltip，而「写实占 31%」这种结论恰恰最容易被截图引用。

### 7. 有意删除四个控件

删掉「全部比例」「只看有 sref」「sref 码」「只看可信拆解」，换成两排分类多选。

| 删除项 | 代价 |
|---|---|
| 全部比例（36 种） | 全库唯一**确定**的结构化维度不再可筛。卡片与导出仍显示比例 |
| 只看有 sref（82 条） / sref 码（96 个） | 不能再按风格码筛。灯箱与导出仍显示码值 |
| 只看可信拆解 | 它只是 `decomp` 多选的一种写法，删掉按钮后能力仍在（直接勾手工 + 逐条） |

这是**范围收窄而非功能退化**：用「确定但只描述版式」的维度，换「可解释但属推算」的内容维度。代价是真实的，记在这里而不是等下次有人问「为什么比例不能筛了」。

### 8. 已下线的三个 URL 参数静默丢弃

`aspect` / `sref` / `srefCode` 在解析时被静默丢弃（不弹「已忽略」提示），但仍会把它们从地址栏抹掉。理由：老链接的筛选意图已无法复现，提示一句也无助于用户理解该改什么；而地址栏挂着失效参数会让复制出去的人以为筛选还在。其它不认识的参数仍按 ADR-0010 提示一次 —— 这条豁免不外扩。

### 9. 运行时现算，不烘焙进产物

`webui/js/sample-taxonomy.js` 是唯一实现，用 `WeakMap` 按作业对象缓存。改一条正则不必重建 3 MB 的 `data-explore.js`（与 `job-key.js` / `phrase-index.js` 同一取舍）。实测全量 971 条分类 **47 ms**（含缓存写入），首渲一次即可；首页计数不调用本模块，避免重演 `viewCount` 白付 690ms 的事故（第 12 步）。

## 考虑过的选项

| 选项 | 为什么没选 |
|---|---|
| **A. 做成真正的树（选写实才展开人像）** | 想看「所有人像」得逐媒介勾一遍，恰好违背用户的原始诉求 |
| **B. 二维矩阵面板（格子点选）** | 7 × 7 在 404px 侧栏放不下，窄屏必炸；且矩阵表达不了「整列」；要另写一套浮层组件 |
| **C. 未声明默认归「写实」** | 把推断写成事实，且不可逆。写实会从 304 变成 602 |
| **D. 不设「未判定」档** | 选任何具体档时这批样本被静默排除，用户不知道少了 170 条 |
| **E. 复用风格榜「题材」8 类** | 其中没有科幻 / 图形，细度也不匹配；会让两套语料互相污染词义 |
| **F. 只做一层（媒介），不做主体** | 用户的例子明确要求「不同媒介下都有人像」 |
| **G. 用 `tags.style` 直接当分类** | 187 种长尾词，且只覆盖 413/971；回答的是「用了什么风格词」而不是「是什么图」 |
| **H. LLM 打标** | 可信度最高，但需 `MJ_DECOMPOSE_API_KEY`（环境无 `.env`）。字段结构已留 `source`，将来换来源不必改界面 |

## 后果

- **正面**：研究样本库第一次能按「怎么画 / 画什么」筛选，且两者可组合（二次元 × 人像 = 15 条；人像不分媒介 = 407 条）。
- **正面**：两轴各自可加总（= 971），有断言钉住；哪天规则变成一条多处命中，断言会先红。
- **正面**：`explain()` 能说出「凭哪个词、在哪一层、什么强度」判的 —— 规则调参与人工复核都不再只能看结论。
- **代价**：**规则精度没有任何独立验证**。只能保证每条恰好归入一档、计数可加，不能保证「自然 167 条」里没有误判（背景有花就判风景的情况已看到）。要让数字可信必须跑 LLM 打标。
- **代价**：删掉比例与 sref 筛选后，这两类研究问题在界面上做不了（数据仍在卡片与导出里）。
- **代价**：工具栏从 9 个控件降到 7 个，但两轴标签更长（`表现媒介 · 规则推算`），窄屏下更挤。窄屏页签遮挡是既有缺陷，本轮未处理。
- **约束**：档位 `value` 是稳定 ASCII slug（进 URL 与导出），`label` 只用于显示。改 label 安全，改 value 会让旧链接失效。

## 修订 2026-11-12：词表手术 + 精度代理基线

**状态：本 ADR 的裁决全部保留，正文「后果」第 4 条的「规则精度没有任何独立验证」由本节修订。**
分布数字以本节为准（上表是本轮首次落地时的快照，保留作对照）。

### 起因

遗留项里挂着「规则精度无独立验证，LLM 打标需 API key」。不用 LLM 也能验：拆解结果自带
`decomposition.framework`（`人物画像` / `物体描述`），它与主体轴应当强相关，可当**独立第二信号**对质。
对质结果：523 条两边都判得出，一致 433 条，**一致率 82.8%** —— 抽查 90 条不一致，
多数是 framework 自己标粗，但挖出四类**分类器确定的错**：

| 误判源 | 实测证据 | 影响 |
|---|---|---|
| 中文单字词条 | 「自然」命中「自然长发」、「海」命中 chibi 小猫条、「花」命中速写咖啡馆与静物蜡烛 | 59 条（自然14 / 海21 / 花12 / 树6 / 山2 / 雪2 / 雨1 / 云1） |
| `kids` 在 person 强词表 | 「Animals for kids」「kids drawing」「for kids」 | 4 条，全错 |
| `face` 在 person 强词表 | 「画面中央是一张贴纸」「银质粉盒特写」 | 19 条，部分错 |
| 骑手 vs 坐骑 | 「cowboy on a horse」「outlaw on horseback」判成动物 | 12 条中约 5 条错 |
| 漏判 | 「a sweet couple hug」落进未判定 | 3 条 |

### 决定

1. **中文词条一律两字以上**（两轴都适用）。单字在中文提示词里几乎都是修饰语，
   结构上无法与主体词区分；这条不是「让词表更准」，是挡住一整类「单字撞词」。
   55 处单字改写为多字（`自然→自然风光/自然景观`、`海→海洋/海面/海滩/海景`、
   `花→花朵/花瓣/花海`、`山→山脉/山峰`、`树→树木/树林/树枝`、`雪→雪山/雪景/积雪`、
   `雨→雨夜/雨景`、`云→云海/云层`、`雾→雾气`、`岛→岛屿`、`桥→桥梁`、`塔→塔楼`、
   `鞋→鞋子`、`猫→猫咪` 等）。
2. `person` 强词表删 `face|faces`、`kid|kids`，补 `children`。按「宁可少判不可错判」，
   真正的肖像由 `portrait` 覆盖；儿童主体由 `child|children` 覆盖。
3. `person` 强词表补 `couple|couples|cowboy|cowgirl|jockey|outlaw|horseback|rider(s)`
   与中文 `情侣/夫妻/牛仔/骑手/设计师/摄影师/画家/厨师`。骑手类样本靠 person 规则
   先于 animal 命中而修正（同一 tier 内按规则声明顺序取先命中）。
4. 新增两条断言：**中文词条两字以上**（另加一条「中文词表非空」防它空转通过）、
   **framework 一致率 ≥ 80%**（当前 83.6%，阈值留措辞抖动余量）。

### 结果

| 项 | 修订前 | 修订后 |
|---|---|---|
| subject 分布 | 人像 407 / 未判定 170 / 自然 167 / 动物 90 / 建筑 87 / 静物 33 / 科幻 17 | 人像 **427** / 未判定 **191** / 自然 **128** / 动物 **85** / 建筑 **90** / 静物 33 / 科幻 17 |
| medium 分布 | 304 / 298 / 254 / 31 / 30 / 30 / 24 | 不变（本轮不动媒介词表） |
| 两轴求和 | 971 | 971 |
| framework 一致率 | 82.8%（433/523） | **83.6%（437/523）** |
| 四个旧错案 | 自然长发→nature、Animals for kids→person、outlaw on horseback→animal、couple→unknown | 全部改正：person / animal / person / person |

未判定从 170 涨到 191 是**预期方向**：删掉 `face` 后一批「只有一张脸」的样本退回未判定，
这是「把不确定显式化」，不是精度倒退。

### 边界

- framework 一致率是**代理指标不是真值**：framework 自己也会错（`A cute Pixar-style cartoon wolf`
  被拆解标成「人物画像」）。它只能抓「词表回归」，不能替代人工标注。
- 真要给出 precision 仍需人工盲测（建议 60 条）；LLM 打标路径仍缺 `MJ_DECOMPOSE_API_KEY`。
- 90 条不一致清单未进 UI（导出留待需要时再做）。
