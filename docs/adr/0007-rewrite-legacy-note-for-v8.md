# 实战笔记按 V8.2 改写后入库，原文作历史附录

《Midjourney 情绪版 / 风格参考 / 漂移控制 / 前置图 实战笔记》里的**三套漂移控制策略全部使用 `--cref`**，而 `--cref` / `--cw` 只在 V6 / Niji 6 有效，V7 起由 Omni Reference（`--oref`）取代、V8.1 起由 Edit Model（`--edit`）取代——**三条策略在 V8.2 下全部无效**。笔记另有四处问题：`--style raw`（V7+ 已由 `--raw` 取代）、`--p` 与 `--sw` 同现（官方不兼容）、`--iw` 范围写成 0–2（V7/V8.1 实为 0–3）、`--s` 一词被用来表达"情绪板跟随强度"（官方语义只有"风格化强度"）。决定：按官方口径**改写后入库**——`--cref`→`--edit`、`--style raw`→`--raw`、`--p`+`--sw` 拆成两条互斥路径、`--iw` 改 0–3、`--s` 拆成两个术语；原文与失效原因对照放进 `references/legacy-note.md` 作为历史附录。

## 考虑过的选项

- 原样入库，逐条标注"V8.2 下此写法无效"：读者（和 agent）仍会照抄无效写法。一份教人写无效 flag 的技能比没有技能更糟。
- 只保留思路、删掉所有具体 flag：会丢掉"策略怎么落地"的信息，而那正是这份笔记最有价值的部分。
- 整份笔记废弃：漂移控制的**思路**（四类漂移、权重优先级、`--iw` 分档、SOP 自检）在 V8.2 下完全成立，过时的只是 flag 名。

## 后果

- 技能内容与用户自己那份笔记相左，属于有意为之。改写依据与原文对照集中在 `legacy-note.md`，不在别处分散。
- `--cref`→`--edit` **不是简单改名**：`--edit` 最多带 4 张参考图，且**没有 `--cw` 那样的角色权重刻度**。锁脸要改成"多传正面 + 标准 45° 侧面几张图"，这改变了原文"用 `--cw 100` 锁脸"的用法。
- 同样地，原文"`--p` + `--sw` 一起用"被官方不兼容性切断，改成"带 `--p` 就不写 `--sw`"或"放弃 `--p` 单独用 `--sw`"两条路径。
- `legacy-note.md` 是历史附录，不是可用写法。agent 照抄那里的示例就是在写 V8.2 的无效提示词。
