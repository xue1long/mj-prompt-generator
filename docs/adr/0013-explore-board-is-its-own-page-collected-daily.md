# 探索榜是独立页面，数据由本项目自己每日重采

隔壁仓 `ai-video-imge-prompts` 镜像了 Midjourney 官网 Explore 榜（1016 条社区作业、4064 张成图）。现在要把这份内容搬进本项目的提示词库，**单独一个页面**。

## 决定

- **页面**：顶层独立页 `#/explore`，占满整屏，不显示左栏的已选提示词 / 最终提示词 / 参数区。它不是提示词库里的第 8 个页签——右栏只有半屏宽，四格成图与提示词原文挤不下，而且"看别人做的成品"与"自己组装提示词"是两种任务。AppHeader 放「工作台 / 探索榜」两个入口，探索榜页有「← 返回工作台」。
- **数据**：数据有两条来路，合起来才是一条完整的时间线。
  - **一次性导入**：隔壁仓 `ai-video-imge-prompts` 已经采了 6 天榜单（1016 条作业 / 4064 张 640px 图）。用 `tools/collect-explore.ts --import` 把它的 `manifest.json` 与本地缩略图导进来（图重编码成 320px，469 MB → 约 70 MB），页面一装上就有历史可看。
  - **每日自采**：此后每天由本项目自己打上游匿名接口 `GET https://www.midjourney.com/api/explore?page=N&feed=top`（每批 4 页 × 50 = 200 条作业）→ 下载四格缩略图 → 重编码成 320px WebP 存进 `public/explore/thumbs/` → 生成 `config/explore.yaml` 快照。
  - 两条来路的数据合并口径：**按作业 id 合并**；同一天重采时**整批替换**（榜单一天里会换好几次，不替换的话一批会越滚越大）。
- **每日更新**：`npm run update:explore` = 采集 → 生成快照 → `npm run build`。产物 dist 每次都是最新的。
- **保留窗口**：只留最近 14 天（批次），旧的连图一起清。
- **筛选**：日期 / 宽高比（用上游声明值）/ 有无风格参考码 / 搜索，状态写进 URL hash（`#/explore?d=…&ar=…&sref=1&q=…`），沿用 ADR-0010「hash 是筛选状态的唯一来源」。排序按入队时间倒序。
- **交互**：作业**不是**提示词条目。点一下只做两件事：把整条社区提示词填进「主体与环境」、把码填进 `--sref` 参数位。**不进「已选提示词」**。
- **入库前过滤**：提示词短于 20 字符的作业不入库；作者名是 UUID 的显示成「匿名作者」。

## 考虑过的选项

- **直接读隔壁仓的 manifest.json**：零采集成本，但隔壁仓每天在换榜，本项目会越用越旧；且数据归属必须跟着源仓走，源仓一改这里就坏。折中：**先一次性导入它的存量数据**（页面一装上就有历史可看），此后每天由本项目自己采，两条来路按 id 合并。
- **完全不碰隔壁仓的数据**：数据线只有一条，听起来干净，但页面刚装上时几乎是空的，用户要等 14 天才攒够可看的东西。而隔壁仓的 6 天存量就在隔壁——先导入、再自采，才是"迁移 + 持续更新"的完整含义。
- **运行时 fetch 本地 JSON**：file:// 下被 CORS 拦，dist 双击即用这个前提就没了。仍走构建期内联（与 `config/styles.yaml` 同一套机制）。
- **采集结果直接写进 dist/**：改数据不用重新构建。但 `vite build` 默认清空 dist，任何一次手动重建都会抹掉当天的图，页面开天窗。
- **把作业当提示词条目进「已选提示词」**：能凑出"社区提示词 + 我的片段"的组合，但一条作业是**整条成品提示词**，不是可拼的片段；混进去会同时破坏"提示词条目 = 可选片段"这个术语和最终提示词的语义。改为填进「主体与环境」——那本来就是唯一由用户自由书写的部分。
- **收全量历史**：相邻批次零重叠，日更 200 条 → 一年 3650 条作业、14600 张图，图是硬约束。这一页的价值是"看新灵感"，所以按 14 天滚动。

## 后果

- **授权变了**：Midlibrary 是"有条件"（站方书面许可，署名 + 回链）；探索榜原本是"禁止再分发"，现在已取得许可、可分发。两者的条件不同，NOTICE 分开写。
- **页面条数与上游对不上**：过滤后少于上游的条数（提示词过短的作业被丢弃）。页脚要写明数据来源与许可，别让人以为这就是上游全量。
- **采集要过 Cloudflare**：`cdn.midjourney.com` 按客户端指纹放行，带 `__cf_bm` 通行证的 curl 通道才稳。采集器以 Node 为主通道、curl 为兜底（见 `tools/collect-explore.ts` 的注释）。
- **采集失败即中止**，保留上一份快照与旧图：宁可给旧数据，也不让页面开天窗。
- **导入的数据与自采的数据同源同构**：都来自上游 Explore 榜，字段含义一致，页面上看不出哪条是哪天导入的——这是有意的：用户看的是内容，不是数据来源的批次。
- 隔壁仓的 `sites/midjourney-explore/NOTICE.md` 仍写着"禁止再分发"，那是隔壁仓自己的文件，不在本项目范围内，但已过时。
