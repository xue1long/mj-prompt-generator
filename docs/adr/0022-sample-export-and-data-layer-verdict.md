# 4.1 本地数据层：范围经实测收敛为「样本导出」

> **状态**：accepted（2026-11-11）
> **决策来源**：《第一性原理校验报告》4.1 节 + grilling 第 10 步 AskUserQuestion 用户拍板（「第 10 步范围」→ 只做导出；「报告修正」→ 就地标注证伪 + 保留原文）。
> **配套**：`docs/第一性原理校验报告.md` 4.1 节「实测复核」、`docs/adr/0017-static-webui-replaces-vue-spa.md` Round 17（实施编年）。

## 决定

报告 4.1 原设想的「本地数据层」重构**整体不做**，只做其中经实测成立的一条：**按当前筛选导出研究样本集**（JSON / Markdown 双格式）。

具体落地：

| 项 | 内容 |
| --- | --- |
| 新增 | `webui/js/sample-export.js` —— 导出模块 |
| 新增 | `tests/sampleExport.test.ts` —— 17 个用例 |
| 改动 | `webui/js/explore-board.js`（toolbar 加导出菜单、`matches()` 对外暴露）、`webui/index.html`、`scripts/verify-webui.mjs`（+6 条断言）、`CONTEXT.md`（+2 条术语）、`README.md` |
| 不做 | 作业/拆解落 IndexedDB、筛选下沉到数据层 |

## 为什么难逆转

- **它推翻了报告里一条 P0 级别的重构结论。** 4.1 被列为「这是最该重构的一处」——「它是『生成器架构』与『研究工作台架构』的根本分歧点，其余改动都可以在旧架构内打补丁，唯独这一条不行」。这个判断如果不留档，下一个人读到报告原文还会去做一遍。
- **它确立了 `file://` 双击即用与「运行时按需读文件」互斥。** 这条约束是**架构级**的：选了一个就永久放弃另一个。ADR-0003「配置在构建期内联，运行时零请求」此前只是一条取舍，现在升级为硬约束。
- **证伪过程本身要可复核。** 本 ADR 记录的是「为什么不做」，比「做了什么」更需要留档 —— 做的部分代码里有，不做的部分只有这里有。

## 实测依据

### 一、报告 4.1 的两条核心论据被推翻

| 报告原文 | 实测 | 判定 |
| --- | --- | --- |
| 每天 +200 条 × 365 天 ≈ 73,000 条 → `data-explore.js` 膨胀到 **230 MB**，单文件 `<script>` 直接不可用 | 采集链是 **14 天滚动窗口**：`tools/collect-explore.ts:62` `DEFAULT_WINDOW_DAYS = 14`；`pruneToWindow()`（`:255-259`）按批次日只留最近 14 天；`replaceBatch()`（`:243-252`）让同批次整体替换。实测 8 批次 / 971 条封顶 | **✕ 前提不成立** |
| `core.js:199-208` 的 `saveSession()` 用 localStorage 存研究笔记，容量约 5 MB **必然触顶** | localStorage 只有三处用途：主题（`core.js:83/91`）、会话参数（`:210/241`）、收藏位（`explore-board.js:79/92`）。**研究笔记从不在 localStorage 里** —— 第 6 步已落 IndexedDB | **✕ 事实错误** |

### 二、一条原报告未测的硬约束

**`file://` 下 origin 为 `null`，`fetch` / `XMLHttpRequest` / 动态 `import()` 全部被 CORS 拦截。**

实测（本机 Chrome，`file://` 打开 `webui/index.html`）：三种方式全部 `net::ERR_FAILED`，控制台报 `Access to fetch at 'file://...' from origin 'null' has been blocked by CORS policy`。

这条约束直接否掉两条要求：

- **作业落 IndexedDB** —— 数据要先到达页面才能落库，而到达页面只能靠 `<script>` 内联（fetch 被拦）⇒ 落库前已拿到全量 ⇒ **落库只是多复制一份，零查询收益，还多一次全量写入**。
- **筛选下沉到数据层** —— 现有筛选实测 1.22 ms（全文筛）/ 0.31 ms（分面计数），已在感知阈值以下；下沉后每页都要等 IndexedDB 事务往返 ⇒ **净变慢**。

同时它证实 ADR-0003 不是可随手推翻的取舍，而是 **`file://` 双击即用场景下的前提**。

### 三、性能基线（当前）

| 项 | 实测 |
| --- | --- |
| `data-explore.js` | 2.49 MB / 971 条 |
| 首屏 load | 267 ms |
| JS 堆 | 23.4 MB |
| 全文筛（971 条） | 1.22 ms |
| 分面计数 | 0.31 ms |

## 考虑过的选项

| 选项 | 否决理由 |
| --- | --- |
| **照报告原方案做全量数据层** | 实测收益为零或负，且会牺牲 `file://` 双击即用能力（需要 fetch 读种子）。改架构比改局部更省事的前提是「现状与目标冲突」—— 实测后这个前提不成立 |
| **导出 + 生成日期筛选维度** | 本步只把真实日期**带进导出**，不加筛选入口。批次口径的完整修法属报告 2.7，与第 13 步（2.5 / 2.7 / 2.8）一并做更省事 |
| **跳过第 10 步，直接做第 11 步** | 4.1 确实是真缺口（样本集不可导出、且没有 Markdown 格式），导出能力零架构成本、不引入回归。直接跳过会留一个已知缺口 |
| **就地把报告原文改成实测后的版本** | 原文是「为什么当时这么判断」的推理链，删掉就丢了。改为就地标注证伪 —— 保留推理链，同时不让读者读到过时论据而不自知 |

## 后果

- **`CONTEXT.md` 新增「生成日期」与「导出样本集」两条术语** —— 前者把「采集批次」与「生成时间」两个口径在语言层面彻底分开（报告 2.7 的语言部分），后者定义导出语义。既有措辞未改动（Q14 冻结项仍不动）。
- **报告 4.1 保留原文 + 就地加「实测复核」块** —— 与 3.2 节处理 ADR-0017 Round 4 前提证伪的做法一致。
- **导出的是筛选命中的全量，不是分页后显示的部分** —— 页面默认渲染 60 条；只导已渲染部分会**静默丢数据**，那比不导出更危险。这条已写成 verify 断言。
- **导出必须带引用键** —— 否则外部拿到的是无法回指的孤立文本。回到工作台用 `#samples?job=<引用键>` 直达。
- **`EXPLORE_BOARD.matches()` 改为对外暴露** —— 导出模块取数靠它，不复刻筛选逻辑（复刻 = 两处漂移 = 导出与界面显示不一致）。
- **报告 4.1 提到的「按时间做 diff」本步不做** —— 前提是本地持有历史快照，而采集链按 14 天窗口滚动替换、历史数据不留存 ⇒ 无 diff 可做。此前提原报告未复核。

## 明确不做的事

- **不做作业/拆解落 IndexedDB** —— 实测证明零收益。
- **不做筛选下沉到数据层** —— 实测证明净变慢。
- **不做导入** —— 报告 4.1 未提；导入要解决冲突合并与去重，是独立的设计问题，不夹带。
- **不做按真实生成日期的筛选** —— 留给第 13 步与批次口径一并改。
