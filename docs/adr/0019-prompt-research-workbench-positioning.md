# 定位转型：从提示词生成器到提示词研究工作台

> **状态**：accepted（2026-11-10）
> **决策来源**：2026-11-10 的 grilling 六轮（Q1 定位 / Q2 闭环必补段 / Q3 数据边界 / Q4 交付边界 / Q5 架构红线），Q1–Q5 均按推荐裁决。
> **配套**：分析与三类清单见 [`docs/第一性原理校验报告.md`](../第一性原理校验报告.md)；术语见 `CONTEXT.md`。

## 决定

本项目的主轴从「把摄影术语组装成一条提示词」改为「**以真实社区生成为素材，研究什么样的提示词产出什么样的画面**」。组装提示词降级为研究闭环中的「复用验证」一步，不再是产品的定义。

三条边界随之确定：

1. **数据边界**——只有 Midjourney 探索榜的社区作业是**社区数据（证据集）**。官方风格榜（styles_top）与 Midlibrary 风格库是**参照语料**，摄影词库的 156 条是研究者自己的**先验假设集**。证据集与假设集不合并，但必须能对质：从社区样本抽出候选词条，用对照检验后并入词库。
2. **闭环必补段**——研究相对浏览的差异只有三段：**溯源**（样本有稳定引用键，结论能回指证据）、**对照**（固定变量并排比较）、**记录**（观察记录与结论可落盘、可聚合查询）。其余环节沿用现状，不做增量优化。
3. **架构红线放宽**——「纯前端、本地离线」仍然保留，但**不再要求构建期全量烘焙**。允许引入本地数据层（IndexedDB / 本地 SQLite），用于支撑可查询、可增量、可导出。仍不引入远程服务。

## 为什么难逆转

产品定位决定三件已落地的事：页签从属关系（探索榜是词库的一个页签）、术语模型（`CONTEXT.md` 里「作业」被定义为成品而非片段）、以及数据链路的重点（采集与拆解，而非组装规则的完备性）。改回去等于把这三件事全部推翻。

## 考虑过的选项

| 选项 | 否决理由 |
|---|---|
| **B 并列加层**：生成器照旧，另开独立研究视图 | 同一份社区数据会在两套界面里各活一次，正是要消除的重复；且用户对同一个东西有两个名字 |
| **C 仅作评估标尺**：产品方向不动，本次只出清单 | 「重构」类结论没有落点；且现状的术语冲突会持续积累 |
| **把 156 条词库也当素材** | 词库是人工编纂的先验，把它当证据会毁掉「证据 / 假设」这条界线，也让「重复需合并」的判断完全不同 |
| **允许远程后端** | 与本地离线的交付形态冲突；研究数据不出本机是当前前提 |
| **不做对照功能，只做记录** | 没有对照的记录是摘抄，不是研究。两者是一起成立的 |

## 后果

- **`CONTEXT.md` 术语已改**：「作业」→「研究样本」，新增「拆解 / 观察记录 / 对照 / 结论 / 采集批次 / 研究样本库」；「探索榜是第 9 个页签」这句与实现不符（实际 6 个页签）的表述一并移除。
- **探索榜要从属关系待改**：本轮只裁决「研究样本库与提示词库在『工作台』层并列」，具体改动属实施阶段，不在本 ADR 范围内。
- **`sref` 断链是首个待修项**：`config/explore.yaml` 有 81 条真实 `sref`，但 `scripts/build-webui-data.mjs:121-122` 硬编码为 `null`，且 `scripts/verify-webui.mjs:104` 把这个 bug 固化成了断言。对照研究依赖 sref 码值筛选，这一条必须先修。
- **正式前端不在版本控制里**：`webui/` 整个目录 + 4 个构建脚本 `git ls-files` 为 0。重构前必须先纳入 git，否则任何改动都是无备份操作。
- **拆解输出链有 4 个写者且格式互斥**：`tools/decompose-explore.ts` 写 YAML、`tools/rule-decompose.mjs` 写 JSON，而 `scripts/build-webui-data.mjs:68` 用 `JSON.parse` 读 —— 一旦真的跑 `npm run decompose:explore`，构建链会直接抛错。当前靠 ADR-0017 的文字禁令兜着，但 `package.json` 与 `更新探索榜.bat` 仍在暴露被禁入口。

## 明确不做的事

- 不改代码、不改数据、不删文件（2026-11-10 本轮交付边界）。
- 不重构、不合并——这些属于实施阶段，须按报告第五节的顺序推进，且第一步是把 `webui/` 纳入 git。
- 不自动补齐 889 条规则兜底拆解的精度（属于「自动生成更多拆解」，不在必补段内）。
