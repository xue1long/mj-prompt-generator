# 技能包只写"怎么写"，参数事实引用 midjourney-doc-facts 而不是复制

参数的取值范围、版本归属、废弃状态是**官方文档的事实**，而官方文档会变。本机已有 `midjourney-doc-facts` 技能，装着 105 篇官方文章索引、52 项参数官方结论、53 条带出处的双向断言，以及官方文档自身矛盾的登记。决定：提示词写作技能包**不复制**那份表，只保留一份"V8.2 合法性白名单"（某个参数能不能写进提示词、两个参数能不能同时写），精确取值一律以 `midjourney-doc-facts` 为准。

## 考虑过的选项

- 在技能包里复制一份参数表：副本会随官方文档更新而漂移。本项目 ADR-0002 已经因为上游参数表有事实错误吃过亏（上游给了官方从未有过的 `--q 0.25`），复制就是把这个坑再挖一次。
- 把两个技能合并成一个：事实层与写作层是两种职责。合并后 description 里的触发词会互相污染——两个技能的触发面本来就高度重叠（一个讲"Midjourney 参数"，一个讲"Midjourney 提示词"）。
- 技能里完全不写参数信息：写提示词时必须知道某个 flag 能不能写。完全不写等于让 agent 凭记忆写 `--cref`，那正是最需要避免的失败模式。

## 后果

- 用技能写提示词时，最好同时加载 `midjourney-doc-facts`。分发时两个技能要一起发，不能只发一个。
- 技能包里的"白名单"是**判断依据**，不是**取值依据**。两者冲突时以 `midjourney-doc-facts` 为准。
- 事实层与写作层分属两个技能包、各自独立升级——官方文档变了只刷新 facts 技能，不必动写作技能。
