# Midjourney 提示词写作与控图工作流

> **版本基线：Midjourney V8.2**（官方自 2026-07-24 起的默认版本）
> **参数事实基准：`midjourney-doc-facts` 技能**（官方帮助中心，取用日期 2026-11-03）
> **本技能只讲"怎么写"。** 参数的取值范围、版本归属、废弃状态一律以 `midjourney-doc-facts` 为准——本技能**不复制**那份表，因为复制即漂移。需要查某个参数的准确取值时，去加载 `midjourney-doc-facts`。
> **本技能只出图片提示词。** 视频参数（`--video` / `--motion` / `--bs` / `--loop` / `--end`）不在范围内。

---

## 一、什么时候读哪个文件

| 用户的诉求 | 读这个 |
|---|---|
| 写/改一条提示词，要构图、风格、情绪词 | `references/method.md` + `references/vocab-style.md` |
| 要摄影术语（快门、光圈、焦段、艺术家、灯光方案） | `references/vocab-photography.md` |
| 某个参数能不能写、版本怎么选、哪些组合会打架 | `references/param-whitelist.md` |
| 要一套现成的场景提示词 | `references/templates.md` |
| 短剧/漫剧/批量出图/角色一致/脸漂移/色调跑偏 | `references/drift-control.md` |
| 术语打架、不知道某个词该叫什么 | `references/glossary.md` |
| 看到旧写法想知道为什么不能用 | `references/legacy-note.md` |

**不要一次把所有 reference 都读进来。** 按上表按需加载。

## 二、交付流程

### 第 1 步 · 问清四件事

信息不足就问，不要替用户猜：

1. **主体与动作** —— 谁、在做什么、什么状态
2. **用途与比例** —— 封面 / 海报 / 竖屏短剧 / 产品图 / 头像 → 决定 `--ar`
3. **画面调性与情绪** —— 写实还是插画；希望 / 忧郁 / 紧张 / 温柔
4. **有没有参考素材** —— 角色图 / 风格图 / 构图图；有没有情绪板档案（`--p`）

**追问一个高价值问题**：这次是**出单张**，还是**出系列**（短剧分镜、同一角色的多张图、同一主题的成套图）？系列需求要用 `--edit` / `--sref` / 固定 `--seed`，和单张的做法完全不同。

### 第 2 步 · 选版本

- 默认 `--v 8.2`
- 动漫 → `--niji 7`（**与 `--v` 互斥，只能写一个**）
- 只有在明确需要 `--cref`、`::` 权重、`--q`、`--oref` 时才回退到旧版 → 见 `references/param-whitelist.md` 的「版本决策路径」

### 第 3 步 · 组提示词（七段式）

```
主体, 动作/状态, 细节与环境, 构图与镜头, 光线与色彩, 风格与审美, --参数
```

**主体放最前**（权重最高），**参数统一放末尾**，模块间用英文半角逗号。
结构说明、两套提示词框架、构图五法、镜头感、情感词 → `references/method.md`

### 第 4 步 · 配参数

| 阶段 | `--s` | `--c` | 输出 |
|---|---|---|---|
| 探索（找方向） | 50–150 | 30–50 | `--sd`，便宜试错 |
| 定稿（锁画面） | 100–250 | 0 | `--hd` |

- 减法用 `--no`，比写"不要 xx"有效得多
- V8.2 默认建议带 `--raw`（写实/产品/摄影类），插画/海报类可不带
- 每个参数的合法范围见 `references/param-whitelist.md`

### 第 5 步 · 交付

固定用这个结构，不要只丢一串字符：

```
【最终提示词】
<一条可直接粘贴的英文提示词，含末尾参数>

【为什么这么写】
- 主体与动作：…
- 构图与镜头：…
- 光线与色彩：…
- 风格与审美：…
- 参数：…（为什么是这个 --s / --ar / 要不要 --raw）

【变体】
A. 探索版（关键词堆叠，试构图快）：…
B. 定稿版（描述句，元素关系更明确）：…
C. 排除版（最终提示词 + --no …）：…

【下一步】
- 画面哪块不对 → 指到具体元素（"脸的朝向"、"背景的杂物"）
- 要系列图 → 固定 --seed / 用 --edit 锁角色 / 用 --sref 锁风格
- 要换风格 → 只换风格词，其他不动
```

**语言规则**：提示词正文用英文（中文能跑但精度低，风格词必须英文）；讲解、说明、参数理由用中文。

## 三、硬性红线

写完提示词后逐条自查，任何一条命中就改：

| ❌ 不能写进 V8.2 提示词 | ✅ 正确做法 |
|---|---|
| `--cref` / `--cw` | `--edit`（V8.1+，最多 4 张参考图） |
| `--style raw` | `--raw` |
| `--q` | 无替代（V8.1/8.2 已移除） |
| `::` 多提示词权重 | 重复描述 / 拆分生成 / `--edit` |
| `--v 8` | `--v 8.2` 或 `--v 8.1` |
| `--preview` | 官方无此参数，不存在 |
| `--sw` / `--sv` 与 `--p` 同现 | 二选一（官方不兼容） |
| `--tile` 与 `--edit` 同现 | 二选一（不兼容） |
| 中文标点混进参数 | 全英文半角，空格分隔 |
| `8k, masterpiece, best quality` | V6 之后基本失效，删掉 |
| 一个 prompt 塞 5 个主体 | 拆成多次生成 |
| 期待 MJ 出准确文字 | V8.2 文字渲染当前最佳但不保证拼写，关键文字后期合成 |

完整理由与官方出处见 `references/param-whitelist.md` 与 `references/legacy-note.md`。

## 四、工作流背景（按需展开）

单张出图用七段式就够。要控制"长什么样"而不是"画什么"，用控图手段：

| 需求 | 手段 | 读哪个文件 |
|---|---|---|
| 角色长相一致、局部重绘、扩图、多图融合 | `--edit` | `references/param-whitelist.md` |
| 画风统一、只换内容 | `--sref` + `--sw` | `references/param-whitelist.md` |
| 构图/机位/姿态参考 | 图像提示（垫图）+ `--iw` | `references/method.md` |
| 批量出图不跑偏 | 情绪板档案 `--p` + 固定 seed + 低 `--iw` | `references/drift-control.md` |
| 复现一张图 | `--seed`（V8 是 99% 相同，非像素级一致） | `references/method.md` |
| 全局审美统一 | 情绪板档案 `--p` / `--profile` | `references/drift-control.md` |

## 五、事实刷新

官方文档会更新。本技能的内容与 `midjourney-doc-facts` 同源，但**版本归属、取值范围、废弃状态以 `midjourney-doc-facts` 为准**。

刷新顺序：

1. 更新 `midjourney-doc-facts` 的事实源与取用日期
2. 用 `doc-consolidation` 的 `assert-audit.js` 跑本技能文档，校验参数断言
3. 同步本技能的 `param-whitelist.md` 与 `legacy-note.md`
